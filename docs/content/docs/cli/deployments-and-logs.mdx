Use these commands to build, deploy (from Git, a local folder, or a pre-compiled binary), adopt existing containers, roll back, inspect logs, and open interactive shells inside your running application containers.

## Deploy an application (`rig deploy`)

Queue a deployment for an app and stream its live build and deploy logs over resumable Server-Sent Events (SSE):

```sh
rig deploy [app] [--no-follow] [--attach] [--wait-healthy] [--timeout <duration>]
```

| Flag | Default | Description |
| --- | --- | --- |
| `[app]` | Linked `rig.toml` app | App name, `project/app`, or UUID. |
| `--no-follow` | `false` | Return immediately as soon as the deployment is queued without streaming logs. |
| `--attach` | `false` | If a deployment is already in progress (`409 Conflict`), automatically attach to its live log stream instead of prompting or failing. |
| `--wait-healthy` | `false` | After the deploy stream finishes, poll the app status until it confirms `running` (`current_deployment_id` live). Useful for strict CI gates. |
| `--timeout <dur>` | `30m` (server) | Abort waiting if the deployment takes longer than `<dur>` (for example `10m`, `300s`, `1h`), exiting with code `5`. |

### Resumable SSE streaming and `Ctrl-C` detach

- **Automatic stream recovery:** If your laptop's Wi-Fi or VPN drops mid-build, `rig` tracks the last received log sequence number (`seq`) and automatically reconnects up to 5 times (`200ms`, `500ms`, `1s`, `2s`, `4s` backoff) passing `?after=<seq>` and `Last-Event-ID: <seq>` so no log lines are missed or duplicated.
- **Safe `Ctrl-C` detach:** Pressing `Ctrl-C` while following a deployment never cancels the server build. Instead, `rig` detaches cleanly with exit code `130` and prints:
  ```text
  Detached. Deployment 91caec40 continues on the server. Follow it with: rig deployments logs 019a1e2d-...
  ```
  To actually cancel a running build on the server, run `rig deployments cancel <id>`.

## Local folder and binary deploys (`rig up`)

Deploy a local project directory or a pre-compiled Linux ELF binary straight from your workstation to a Rig server without committing or pushing to Git:

```sh
rig up [path] \
  [--node <vm>] \
  [--app <app>] \
  [--project <project>] \
  [--binary <path>] \
  [--remote-build] \
  [--port <port>] \
  [--dockerfile <path>] \
  [--health-path <path>] \
  [--base-image <image>] \
  [--arg <arg>...] \
  [--no-follow] [--wait-healthy] [--timeout <duration>]
```

| Flag | Default | Description |
| --- | --- | --- |
| `[path]` | `.` (current directory) | Project directory or pre-compiled Linux ELF binary path. Passing a regular file automatically enters Direct Binary Mode. |
| `--node <vm>` | Active context / `rig.toml` | Target Rig server (saved context name or server URL). |
| `--app <app>` | Linked `rig.toml` or folder/binary name | Target app name, `project/app`, or UUID. Auto-creates a `local` app on first run when unambiguous. |
| `--project <project>` | Sole project or `rig.toml` | Project name, slug, or ID used when creating a new local app. |
| `--binary <path>` | Auto-detected when `[path]` is a file | Force Direct Binary Mode for a pre-compiled Linux ELF executable (no Dockerfile required). |
| `--remote-build` | `false` | Stream a minimal `zstd`-compressed delta tarball and build on the Rig server instead of building the OCI image locally. |
| `--port <port>` | `rig.toml` or `8080` | Container port the app listens on. |
| `--dockerfile <path>` | `Dockerfile` or `Containerfile` | Relative Dockerfile/Containerfile path inside the directory. |
| `--health-path <path>` | `rig.toml` or TCP check | HTTP health check path (for example `/health`). |
| `--base-image <image>` | `scratch` (static) / `distroless` (dynamic) | Base image override for Direct Binary Mode. |
| `--arg <arg>` | None | Default command-line arguments passed to the binary (repeatable). |

### Deploy modes and deduplication

- **Source Mode (local build — default):** When a `Dockerfile` or `Containerfile` exists and local `podman` or `docker` is installed, `rig up` builds the OCI image locally (keeping server RAM free), checks the server's SHA-256 blob cache (`POST /api/v1/uploads/blobs/check`), streams only changed `zstd`-compressed layers, loads the image on the server, and runs a health-checked zero-downtime swap.
- **Source Mode (remote delta build — `--remote-build` or fallback):** Walks the directory respecting `.gitignore` and `.dockerignore`, computes SHA-256 file hashes, uploads only changed files in one `zstd` delta tarball, and builds remotely via `Dockerfile`, `Containerfile`, or Railpack.
- **Direct Binary Mode:** Validates ELF magic and `PT_INTERP` headers. Statically linked binaries (e.g. Rust `musl` or Go `CGO_ENABLED=0`) are wrapped directly in a pure-Rust `FROM scratch` OCI image with zero network pull; dynamically linked Linux ELF binaries are wrapped onto `gcr.io/distroless/cc-debian12:nonroot`.

```sh
# Build locally and push only changed zstd layers to your prod context
rig up --node prod

# Force a remote delta build on the server (respecting .gitignore and .dockerignore)
rig up --node prod --remote-build

# Deploy a statically linked Rust binary directly with zero Dockerfile
cargo build --release --target x86_64-unknown-linux-musl
rig up ./target/x86_64-unknown-linux-musl/release/api --node prod --port 8080 --health-path /health
```

## Adopt existing containers (`rig adopt`)

Discover running Docker/Podman containers, Docker Compose stacks, or Coolify/Dokploy workloads on a Rig server and migrate them into Rig with zero downtime and automatic rollback (<RoleBadge role="Admin" /> required):

```sh
rig adopt [containers...] \
  [--node <vm>] \
  [--project <project>] \
  [--app <name>] \
  [--port <port>] \
  [--health-path <path>] \
  [--domain <host>...] \
  [--secret <key>...] \
  [--plain <key>...] \
  [--dry-run] \
  [--export-quadlets <dir>] \
  [--write-rig-toml <dir>] \
  [--keep-old | --remove-old]
```

| Flag | Default | Description |
| --- | --- | --- |
| `[containers...]` | Interactive multi-select | Container names, IDs, or Compose stack names to adopt. |
| `--node <vm>` | Active context | Target Rig server (saved context name or server URL). |
| `--project <project>` | Interactive select / sole project | Target Rig project to register adopted apps under. |
| `--app <name>` | Service/container name | Override the created Rig app name (single container only). |
| `--port <port>` | Auto-detected | Override detected container HTTP port (single container only). |
| `--health-path <path>` | Auto-detected or TCP check | Override HTTP health check path. |
| `--domain <host>` | Auto-extracted from Traefik/Caddy/`VIRTUAL_HOST` | Explicit domain hostname(s) to register (repeatable). |
| `--secret <key>` / `--plain <key>` | Auto-classified | Override which environment variable keys are stored as vault secrets vs. plain text (repeatable). |
| `--dry-run` | `false` | Print the full preview (`rig.toml`, Quadlet `.container` / `.network` files, mounts, domains, secrets, and warnings) without modifying anything. |
| `--export-quadlets <dir>` | None | Write generated Podman Quadlet `.container` and `.network` unit files to `<dir>`. |
| `--write-rig-toml <dir>` | None | Write generated `rig.toml` file(s) to `<dir>`. |
| `--keep-old` | `false` | Leave the old container running alongside the adopted one after cutover. |
| `--remove-old` | `false` | Permanently remove the old container after stopping it (by default Rig stops it cleanly and keeps it as a backup). |

```sh
# Inspect unmanaged containers interactively and preview before touching anything
rig adopt --node prod --dry-run --export-quadlets ./quadlets

# Adopt a Compose stack or single Coolify container with confirmed cutover
rig adopt billing-api --node prod --project production
```

- **Zero data movement:** Host bind mounts and existing named volumes keep their exact paths/names (`owned = 0`), so deleting an adopted app in Rig never deletes user host data.
- **Automatic rollback:** If the newly adopted container fails health checks, Rig deletes the failed container, automatically restarts the original container (if it was paused for writable mounts), and cleans up any database rows.

## Start, restart, and stop

```sh
# Start a stopped or failed app (reuses its most recent image when available)
rig start [app] [--no-follow] [--wait-healthy] [--timeout <duration>]

# Restart a running app with a zero-downtime container swap
rig restart [app] [--no-follow] [--wait-healthy] [--timeout <duration>]

# Stop a running app and remove its container (keeps volumes, env vars, and domains)
rig stop [app] [--yes]
```

## Roll back a deployment (`rig rollback`)

Redeploy an earlier container image without rebuilding from Git:

```sh
rig rollback [app] [deployment-id] [--no-follow] [--wait-healthy] [--timeout <duration>]
```

- **Default target:** When `[deployment-id]` is omitted, `rig` automatically selects the most recent `superseded` deployment that has a built/pulled image.
- **Short ID matching:** You can pass the full deployment UUID or **at least 4 characters** of its prefix or suffix (case-insensitive). If the short ID matches more than one deployment, `rig` refuses to guess and lists the ambiguous IDs.

```sh
# Roll back to the previous live deployment
rig rollback production/web

# Roll back to a specific deployment by 8-char suffix
rig rollback production/web 91caec40
```

## Inspect and cancel deployments (`rig deployments`)

```sh
# List deployments for an app (newest first)
rig deployments [app] [--limit <1-200>] [--before <deployment-id>]
rig deployments ls [app] [--limit <1-200>] [--before <deployment-id>]

# Show full metadata, commit SHA/message, image, timestamps, and error for a deployment
rig deployments show <deployment-id>

# Stream or print build/deploy logs for a specific deployment
rig deployments logs <deployment-id> [--no-follow] [--json]

# Cancel a queued, building, or deploying deployment
rig deployments cancel <deployment-id>
```

Example `rig deployments production/web` output:

```text
ID         STATUS       TRIGGER    VERSION    CREATED
91caec40   running      manual     a4f8d2c1   5m ago
7b03e112   superseded   webhook    8c19e04a   2h ago
3d91a004   failed       manual     5e01b92f   1d ago
```

## Stream runtime container logs (`rig logs`)

Stream or query live `stdout`/`stderr` output from an application's running container:

```sh
rig logs [app] \
  [-n / --tail <lines>] \
  [--no-follow] \
  [--since <duration-or-rfc3339>] \
  [-t / --timestamps] \
  [--grep <pattern>] \
  [--json]
```

| Flag | Default | Description |
| --- | --- | --- |
| `-n`, `--tail <N>` | `200` | Number of trailing log lines to fetch (`1–5000`). |
| `--no-follow` | `false` | Print existing log lines and exit immediately instead of streaming live output. |
| `--since <val>` | All retained | Show only logs since a relative duration (`30s`, `10m`, `2h`, `1d`) or an RFC 3339 timestamp (`2026-11-22T15:00:00Z`). |
| `-t`, `--timestamps` | `false` | Prefix each log line with its timestamp. |
| `--grep <pattern>` | None | Filter log lines by case-insensitive substring (evaluated server-side and verified client-side). |
| `--json` | `false` | Emit one JSON `LogLine` (`{"seq":1,"ts":"...","stream":"stdout","line":"..."}`) per line (**NDJSON**). |

```sh
# Tail the last 100 lines from the past 15 minutes matching "error"
rig logs production/api --tail 100 --since 15m --grep error --timestamps --no-follow

# Pipe live NDJSON logs into jq
rig logs production/api --json | jq -r 'select(.stream == "stderr") | .line'
```

## Interactive container shell (`rig exec`)

Open an interactive raw-TTY WebSocket shell (`/bin/bash` or `/bin/sh`) inside a running app container (<RoleBadge role="Developer" /> required):

```sh
rig exec [app] [--cols <columns>] [--rows <rows>]
```

- Automatically detects your local terminal dimensions (`console::Term::stdout().size_checked()`, defaulting to `80x24`).
- Enters local raw termios mode (`cfmakeraw`) with an RAII `Drop` guard that guarantees your local terminal state is restored when the session closes.
- Listens for Unix `SIGWINCH` signals and dynamically resizes the remote container PTY as you resize your terminal window.
