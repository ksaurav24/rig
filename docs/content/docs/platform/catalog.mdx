The **Catalog** page in the Rig dashboard provides 17 curated self-hosted applications (`web/src/lib/catalog.ts`). Each template preconfigures a pinned container image, internal port, HTTP health check path, default memory limit, persistent volume mounts, and auto-generated 32-character secrets.

## How catalog deployments work

When you pick a template from the Catalog:

1. **Project and name:** You choose which project to deploy the app into and confirm or customize the app name (defaults to the template's `id`).
2. **Auto-generated secrets:** Any variable marked with `generate: 'password'` is populated with a cryptographically random 32-character URL-safe secret, encrypted at rest with `Vault`, and masked by default (revealable anytime under the app's **Environment** tab).
3. **Persistent storage:** Templates with stateful data automatically create and attach named container volumes for every path in `volumes`, and deploy using Rig's safe stop-then-start strategy.
4. **Immediate deploy:** Rig creates the app via `POST /api/v1/apps` and immediately queues its first deployment via `POST /api/v1/apps/{id}/deploy`.

## Deploying a catalog template from the CLI

Because catalog templates are standard `image` apps with preconfigured volumes and environment variables, you can also deploy any template directly with `rig apps create`:

```sh
# Example: deploy Vaultwarden from the CLI
rig apps create vaultwarden \
  --project production \
  --image vaultwarden/server:1.37.5 \
  --port 80 \
  --memory 256 \
  --health /alive \
  --volume /data \
  --env "ADMIN_TOKEN=$(openssl rand -base64 24)"

rig deploy production/vaultwarden
rig domains add production/vaultwarden vault.example.com --tls auto
```
