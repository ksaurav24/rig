`rig-server` is the control-plane binary installed at `/usr/local/bin/rig-server`. In production, `systemd` runs `rig-server serve` as the unprivileged `rig` system user, loading configuration from `/etc/rig/rig.env`.

## Global flags and environment variables

Every `rig-server` flag can be passed on the command line or configured in `/etc/rig/rig.env` (`crates/rig-server/src/main.rs`):

| CLI flag | Environment variable | Default | Description |
| --- | --- | --- | --- |
| `--data-dir <PATH>` | `RIG_DATA_DIR` | `./data` (`/var/lib/rig` in systemd) | Directory for `rig.db`, `master.key`, `bin/railpack`, and `backups/`. Created with mode `0700`. |
| `--listen <ADDR>` | `RIG_LISTEN` | `127.0.0.1:7460` | Socket address the HTTP API and embedded dashboard listen on. Keep on loopback so all public traffic enters through Caddy. |
| `--secure-cookies` | `RIG_SECURE_COOKIES` | `false` (`true` when TLS enabled) | Mark browser session cookies `Secure`. Enable whenever serving the dashboard over HTTPS. |
| `--engine-socket <PATH>` | `RIG_ENGINE_SOCKET` | Auto-detected | Unix socket path for Podman or Docker (for example `/run/user/998/podman/podman.sock` or `/var/run/docker.sock`). |
| `--caddy-admin <URL>` | `RIG_CADDY_ADMIN` | `http://127.0.0.1:2019` | Caddy admin API endpoint where `rig-server` pushes route and TLS configurations. |
| `--http-port <PORT>` | `RIG_HTTP_PORT` | `80` | Port Caddy serves plain HTTP and HTTP-01 ACME challenges on. |
| `--https-port <PORT>` | `RIG_HTTPS_PORT` | `443` | Port Caddy serves HTTPS traffic on. |
| `--github-api <URL>` | `RIG_GITHUB_API` | `https://api.github.com` | GitHub REST API base URL (override for GitHub Enterprise Server). |
| `--github-web <URL>` | `RIG_GITHUB_WEB` | `https://github.com` | GitHub web base URL used for the App manifest flow, repository cloning, and CSP `form-action`. |
| `--poll-interval <SECS>` | `RIG_POLL_INTERVAL` | `120` | Seconds between `git ls-remote` branch polls for auto-deploy Git apps (`0` disables polling). |
| `--proxy-dashboard` | `RIG_PROXY_DASHBOARD` | `false` (`true` in `/etc/rig/rig.env`) | Instruct Caddy to proxy the Rig dashboard (either on `dashboard_domain` or as the port `80` fallback). |
| `--public-url <URL>` | `RIG_PUBLIC_URL` | `http://<listen>` | Public URL printed in the first-time setup console message. |
| `--allow-private-alerts` | `RIG_ALLOW_PRIVATE_ALERTS` | `false` | Allow outbound alert webhook channels to connect to loopback or private/RFC1918 IP addresses (for self-hosted LAN receivers). |
| `--allow-private-git` | `RIG_ALLOW_PRIVATE_GIT` | `false` | Allow Git app clones and branch polling against loopback or private/RFC1918 hosts (for self-hosted LAN Git servers). |
| `--enable-api-docs` | `RIG_ENABLE_API_DOCS` | `false` | Enable the authenticated interactive Scalar API reference UI at `/api/docs`. |
| — | `RUST_LOG` | `info,tower_http=warn,sqlx=warn` | Tracing log filter for `journald` / stderr output. |

### Example `/etc/rig/rig.env`

```ini
RIG_DATA_DIR=/var/lib/rig
RIG_LISTEN=127.0.0.1:7460
RIG_PROXY_DASHBOARD=true
RIG_PUBLIC_URL=https://rig.example.com
RIG_SECURE_COOKIES=true
RIG_ENGINE=podman
RIG_ENGINE_SOCKET=/run/user/998/podman/podman.sock
```

After editing `/etc/rig/rig.env`, restart the service:

```sh
sudo systemctl restart rig
```

## Server console subcommands

Run administrative subcommands directly on the server as the `rig` OS user (`sudo -u rig rig-server --data-dir /var/lib/rig <subcommand>`):

| Subcommand | Usage | Description |
| --- | --- | --- |
| **`serve`** | `rig-server serve` | Run the HTTP server and background workers (default when no subcommand is given). On first boot before setup is complete, the one-time setup token is only printed to `stderr` when attached to an interactive TTY (not to `journald` logs). On `SIGTERM` / `SIGINT`, drains any in-flight deployment swap, restores any paused stateful container, and runs `PRAGMA wal_checkpoint(TRUNCATE)` before closing SQLite. |
| **`setup-token`** | `rig-server --data-dir /var/lib/rig setup-token` | Issue and print a fresh 30-minute one-time setup token before an owner account exists. Works while the server is running. |
| **`reset-password`** | `rig-server --data-dir /var/lib/rig reset-password <email>` | Generate a new 15-character temporary password for `<email>` (valid 7 days; must be changed on next sign-in), revoke all active browser sessions and API tokens, clear login rate-limit lockouts, log `auth.password_reset` in the audit log, and print the temporary password once. |
| **`reset2fa`** | `rig-server --data-dir /var/lib/rig reset2fa <email>` | Disable TOTP two-factor authentication, delete recovery codes, and revoke all active browser sessions for `<email>` if they lost their authenticator device. Records `auth.totp_reset` in the audit log. |
| **`dashboard-domain`** | `rig-server --data-dir /var/lib/rig dashboard-domain <host> [--tls <auto\|internal\|tailscale\|off>]` or `--clear` | Set or clear the dashboard's hostname and TLS mode in SQLite. Applied within 60 seconds by a running server, or immediately on `sudo systemctl restart rig`. |
| **`dashboard-access`** | `rig-server --data-dir /var/lib/rig dashboard-access <public\|lan\|tailscale>` | Set who may open the dashboard and API (`public`, `lan`, or `tailscale`). Restart `rig.service` for the change to take effect immediately. |
| **`proxy-detach-dashboard`** | `rig-server --data-dir /var/lib/rig proxy-detach-dashboard` | Internal helper invoked by `install.sh --uninstall`: syncs `rig-caddy` with `dashboard_port: None` so the dashboard route is removed while all running application routes and TLS policies stay online. |
| **`openapi`** | `rig-server openapi` | Print the complete OpenAPI 3.1 JSON specification to `stdout` and exit without touching the database or filesystem. |

## Systemd service hardening (`packaging/rig.service`)

`rig.service` runs `rig-server` inside a strict `systemd` sandbox:

```ini
[Service]
Type=simple
User=rig
Group=rig
EnvironmentFile=/etc/rig/rig.env
ExecStart=/usr/local/bin/rig-server serve
Restart=on-failure
RestartSec=3
TimeoutStopSec=30
UMask=0077
NoNewPrivileges=yes
ProtectSystem=strict
ReadWritePaths=/var/lib/rig
ProtectHome=yes
PrivateTmp=yes
PrivateDevices=yes
ProtectKernelTunables=yes
ProtectKernelModules=yes
ProtectKernelLogs=yes
ProtectControlGroups=yes
ProtectClock=yes
ProtectHostname=yes
RestrictSUIDSGID=yes
RestrictRealtime=yes
RestrictNamespaces=yes
LockPersonality=yes
SystemCallArchitectures=native
CapabilityBoundingSet=
AmbientCapabilities=
RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6 AF_NETLINK
LimitNOFILE=65536
```

- **Read-only root filesystem:** `ProtectSystem=strict` mounts the entire OS filesystem read-only for `rig-server`, with `/var/lib/rig` (`ReadWritePaths=/var/lib/rig`) as the only writable directory.
- **Zero Linux capabilities:** `CapabilityBoundingSet=` and `AmbientCapabilities=` strip all Linux capabilities from `rig-server`.
- **`UMask=0077`:** Guarantees any file created by `rig-server` is accessible only by the `rig` user.
